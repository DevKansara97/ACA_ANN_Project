Every component, step by step

Read these in signal-flow order. The names match the current project.

1Input pins A and B

Each pin carries 25-bit signed fxp(6,18): one sign bit, six integer bits, and eighteen fractional bits. Logisim stores a binary integer; the binary point is our interpretation.

Actual value = signed raw integer ÷ 262144

+1.0 is raw +262144 (0040000 hex). −1.0 is raw −262144 (1FC0000 hex). Setting only the MSB does not turn a positive magnitude into its negative: these are two’s-complement inputs.

2Two sign Splitters

Each Splitter routes bit 24—the most significant input bit—to a one-bit sign wire: SIGN_A or SIGN_B. Zero means nonnegative; one means negative.

The complete input still travels to the magnitude-selection path. We are copying the sign for control, not cutting it off and calling the remaining bits a magnitude. The lower 24-bit Splitter branch is unused.

SIGN_A = A[24]
SIGN_B = B[24]

3Two 25-bit Negators

The Negators continuously calculate NEG_A = −A and NEG_B = −B. Two’s-complement negation is equivalent to inverting every bit and adding one, keeping 25 bits.

They create candidates, not unconditional absolute values. For +3 the candidate is −3; for −3 it is +3. The next MUX decides which version to use.

At the input minimum, −64, negation leaves the same 25-bit pattern. Interpreted as an unsigned magnitude, it correctly represents +64, so this edge case still works.

4Two magnitude MUXes

A MUX is a selector. Input 0 is the original number; input 1 is its negated candidate. The original sign bit selects the input.

Sign = 0 → keep original
Sign = 1 → choose negated candidate

The outputs MAG_A and MAG_B are interpreted as unsigned magnitudes, |A| and |B|. Their binary point still has 18 fractional bits. “Include Enable? No” simply omits the optional enable pin; these MUXes remain active.

5One XOR gate

The XOR remembers the sign the answer should have, using the original signs.

NEGATIVE = SIGN_A XOR SIGN_B

It controls the final selectors; it does not multiply or negate the data itself.

6One built-in Multiplier

The ordinary 25-bit Multiplier calculates MAG_A × MAG_B. Its right output is MAG_LO, the lower 25 bits. Its bottom c_out is MAG_HI, the upper 25 bits.

c_out is a 25-bit chunk here, not a one-bit carry. Together, the two outputs retain all 50 product bits. The 25-bit c_in input is tied to zero so nothing extra is added.

Magnitude = MAG_HI × 2²⁵ + MAG_LO
Fractional bits = 18 + 18 = 36

7Two linked Subtractors

These prepare the full negative candidate, 0 − magnitude. Because the magnitude has two chunks, the subtraction must span both chunks.

NEG_LO = (0 − MAG_LO) mod 2²⁵
NEG_HI = (0 − MAG_HI − BORROW) mod 2²⁵

The low Subtractor’s borrow-in is zero. Its borrow-out drives the high Subtractor’s borrow-in. Borrow is 1 when MAG_LO is nonzero, and 0 when MAG_LO is zero.

They always calculate the negative candidate, even when the final answer should be positive.

8Two final output MUXes

Both use NEGATIVE as their selector.

XOR = 0 → P_HI/P_LO = MAG_HI/MAG_LO
XOR = 1 → P_HI/P_LO = NEG_HI/NEG_LO

We select a complete two’s-complement result. Merely setting the product’s MSB would be wrong. If either input is zero, both positive and negative candidates are zero, so the output remains zero regardless of the XOR result.

The part most likely to be confusing

Why the two Subtractors need a borrow wire

Think of HI and LO as two digits in base 2²⁵ = 33,554,432. Subtracting the low digit can require borrowing from the high digit, just as 1000 − 1 borrows between decimal digits.

MAG_LO is zero

For −1.0 × +1.0, the magnitude is raw 2³⁶:

MAG_HI = 0000800
MAG_LO = 0000000
BORROW = 0
NEG_HI = 1FFF800
NEG_LO = 0000000

The low half does not need a borrow. Signed P_HI is −2048, so the result is (−2048 × 2²⁵) / 2³⁶ = −1.0.

MAG_LO is nonzero

For input raw integers −1 and +1 (tiny fixed-point values), the magnitude product is raw 1:

MAG_HI = 0000000
MAG_LO = 0000001
BORROW = 1
NEG_HI = 1FFFFFF
NEG_LO = 1FFFFFF

The complete 50-bit word becomes all ones: signed raw −1, meaning −2⁻³⁶. Negating the halves independently would give an incorrect high half.

Read HI and LO as one number

Where the binary point belongs

The full result is one sign bit + 13 integer bits + 36 fractional bits = 50 bits, which we call signed fxp(13,36). Logisim 2.7.1 limits individual buses to 32 bits, so the circuit exposes two 25-bit chunks.

raw product = signed_25(P_HI) × 33554432 + unsigned_25(P_LO)
actual value = raw product ÷ 68719476736

Concatenate P_HI first, P_LO second, then place the binary point 36 bits from the right. The two chunks are not separate products, and P_LO alone is not the answer.

The multiplier no longer truncates or rescales its product. Sigma uses its full result. Sign extension happens in sigma when a 50-bit product is widened for addition—not in this multiplier. Quick reference

The remaining pieces are wiring

Two Constants

ZERO25 is a 25-bit zero. It supplies the multiplier’s c_in and the zero operands of both Subtractors.

ZERO1 is a one-bit zero. It supplies the low Subtractor’s borrow-in. Different widths matter: one-bit zero and a 25-bit bus are not interchangeable connections.

Named Tunnels

Tunnels with the same name inside the same circuit are electrically connected. They do not calculate, change a format, or store a value.

Labels such as MAG_A, BORROW, and P_HI replace long crossing wires. Matching names in different subcircuits are separate local nets.
